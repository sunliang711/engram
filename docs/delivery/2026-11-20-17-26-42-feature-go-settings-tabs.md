# 设置子页与 SafeKeep 上传配置统一

## 背景与范围

系统设置与定时备份任务各自保存上传模式、远程路径和目标上游，导致实际生效值不直观。本次将定时任务上传参数统一到系统设置，并按当前已有能力增加设置分类。

## 最终实现

- 系统设置顶部新增「备份与存储」「界面偏好」「账号安全」页签，支持方向键、Home/End、浏览器历史和 `section` URL 参数。
- 备份页统一管理 SafeKeep 地址、密钥、加密口令、上传模式、路径和目标上游。切换子页保留未保存草稿并隐藏已查看的密钥；原有保存状态判断和接口鉴权继续使用。
- 界面偏好复用现有语言、主题能力，并增加知识库默认分页（20/50/100），立即生效、存储于当前浏览器。知识库链接中明确指定的分页优先，浏览器禁用存储时仍可操作。
- 账号安全展示当前管理员，复用已有的修改密码流程及会话失效规则。
- 定时备份仅保存调度和导出内容，抽屉只读展示当前系统上传配置，并提供跳转修改入口。迟到响应不会覆盖已关闭或已切换任务的抽屉。
- 按用户明确选择，采用系统设置原值，清除旧任务中的覆盖值；不会将旧任务的值写回系统设置。

## 代码与接口

- `internal/admin/ui/`：设置页签、偏好、任务摘要及中英文样式与文案。
- `internal/scheduler/builtin_safekeep_backup.go`：移除任务上传参数，上传时复用 SafeKeep 服务的持久化配置。任务配置仍支持 `migration_mode`、`include_deleted`；非空 `upload_mode`、`remote_path`、`targets` 返回参数错误，旧客户端的空字段被清除。
- `migrations/012_unified_safekeep_upload_settings.sql`：仅删除 SafeKeep 备份任务的三个覆盖字段，保留其他任务、导出选项、启停、计划、次数和执行历史。
- 复用 `GET/PUT /api/admin/integrations/safekeep`、管理员密码修改和任务接口，未增加依赖或环境变量。现有备份 API 的单次上传选项接口保持兼容。

## 验证

- Node 前端测试 75 项通过，包含页签导航、URL、浏览器存储不可用、只读配置转义、任务负载及迟到响应。
- `go test -race ./...` 通过；admin、scheduler、migration 测试使用本次新建的独立临时 PostgreSQL 数据库。
- SafeKeep 与旧调度测试另用各自独立数据库运行，覆盖现有服务能力。
- 新迁移测试验证冲突时系统设置保留、旧覆盖清除、任务计划与历史保留、重复迁移无副作用、其他任务不受影响。
- 管理集成测试验证保存系统设置后下一次备份立即使用新模式、路径和目标上游，且旧客户端不能重新加入任务覆盖值。远程上传使用本地 HTTP 测试服务。
- ego-browser 使用本地模拟接口完成深浅色、中英文、390px 窄屏视觉检查；验证设置草稿保留、刷新恢复子页、偏好持久化、默认分页与链接分页优先级、密码修改入口、只读上传摘要及设置跳转。

## 发布与回滚

部署前通过应用自动迁移或手工执行迁移 012。此次明确删除历史任务覆盖值，升级后的备份目标以系统设置为准；如需恢复旧覆盖值，应从升级前的备份中取回。回滚到上一版本无需撤销表结构，缺失的覆盖字段会按旧版本逻辑回退系统设置。
