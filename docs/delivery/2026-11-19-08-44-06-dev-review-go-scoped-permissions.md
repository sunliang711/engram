# 按范围授权：开发与独立评审交付

## 结果与规则

后台登录 `admin` 账户统一负责管理。API / MCP 成员取消 `admin`、`maintainer` 角色，按范围独立授权：

| 范围 | 无权限 | 只读 | 读写 |
| --- | --- | --- | --- |
| 当前租户全局记忆 | `none` | `member` | `global_writer` |
| 单个项目 | 无项目成员记录，提交 `role: none` 撤销 | `reader` | `writer` |

读写包含读取、创建、更新和软删除；恢复、彻底清理、成员与授权管理由后台 admin 负责。全局读写不会授予项目访问权限。新建普通成员缺省为全局无权限；快速接入仍可显式选择全局权限，并为初始项目授予读写。

保留现有 JSON 字段 `tenant_role`、`project_role`，降低客户端兼容成本；`can_maintain_project` 保留并固定返回 `false`。

## 实现范围

- `internal/auth/auth.go`：移除成员管理员隐式权限；后台专用审计身份不参与 API 成员认证。
- `internal/memory/service.go`：仅返回授权范围的发现索引、默认搜索与变更；更新、软删除、缓存重放遵循当前授权；后台恢复与清理校验专用审计身份。
- `internal/notify/listener.go`、`internal/mcp/server.go`：通知按全局与项目权限过滤；无可读范围拒绝建立 SSE，通知发送前及保活时重新验证当前授权。
- `internal/admin/handler.go`：全局无权限支持、项目授权撤销、废弃角色输入拒绝；后台操作不再借用成员管理员身份。
- `internal/admin/migration.go`：旧系统快照导入采用与升级相同的权限转换，保留后台审计归属，禁止恢复成员管理特权。
- `internal/admin/ui/{app.js,index.html,i18n.js}`：全局和项目均展示无权限、只读、读写；支持授予、修改和撤销，删除管理员继承提示，同步中英文说明。
- `migrations/005_scoped_member_permissions.sql`：新增增量迁移；原有迁移文件及校验和不变。
- 更新对应 Go 测试、README 和 DESIGN。未新增依赖、框架或配置项，保留用户已有未跟踪文件 `docker-compose 2.yaml`。

## 升级与数据转换

用户明确选择旧成员 admin 降为无权限：

1. 在其原 admin 所属租户内，撤销全部显式项目授权并将全局权限改为 `none`，需要后台重新授权。
2. 保留该成员在其他非 admin 租户的权限。
3. 普通旧 `maintainer` 项目授权改为 `writer`。
4. 移除后台审计身份的租户与项目成员记录，并吊销其历史 API Token。
5. 清除旧幂等响应缓存，避免旧授权语义下的缓存结果继续使用。
6. 旧系统快照导入执行相同的降级规则。

发布时应使用新服务版本配合迁移 005。默认自动迁移在启动时执行；关闭自动迁移的环境需先应用 SQL。回滚需要恢复升级前数据库备份与匹配版本服务。
